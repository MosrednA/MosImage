# FLUX 3 Image Klein versus current Klein 9B — 15 October 2026

Status: Completed isolated evaluation; not selected for integration. The user requires a small model that is substantially faster or clearly better. Retain Klein 9B as the Quality default.

## Scope and initial result

FLUX 3 Image Klein runs locally on the RTX 5070 Ti 16 GB with the official distilled NVFP4 weights, native Comfy Kitchen CUDA GEMMs and BFL's reference model/sampler. Encoder and renderer run separately. This is an isolated research tool, not a registered MosImage provider or a change of the Quality default.

The primary cohort has **24 successful renders per model**: twelve frozen requests, seeds **7 and 42**, identical full-scene captions, the same provided reference pixels and model-facing dimensions, and shared final compositing. Another **24 Klein current-prompt controls** and **six complete FLUX 3 requests** bring the retained successful cohort to **78 images**. FLUX 3 takes about twice the cached-prompt render time. Visual gains are selective: better reference/identity use and scene instruction following, with remaining scale, grip, glow and local-edit limitations.

## Protocol

The ten existing creative/retouch cases are duo/coaster, DJ, masked sword, whole-image sword, garden mushroom, kitchen removal, embroidered daisy, botanical poster, Anna insertion and reference mug. The coffee-shop typography case comes from the retained Qwen evaluation. A fixed 1024 × 768 garden canvas adds grey strips at both sides for an expansion diagnostic.

Source/mask/reference hashes are checked by the existing fixture helpers. Both arms share the existing context crops, reference padding and final compositor. Single references are fitted to a 16-pixel grid because the BFL VAE cannot patchify an odd latent width; the same fit is applied to Klein. Output/source/mask dimensions use a common 32-pixel grid. For local edits, FLUX 2 receives native mask conditioning; FLUX 3 edits the reference crop and only the shared final compositor enforces the hard protected footprint.

Full-scene captions were frozen before any FLUX 3 outputs were inspected. The primary Klein arm receives exactly those captions. A separate current-prompt Klein arm retains the established application-style prompts, so caption sensitivity is visible rather than attributed entirely to the model. Prompt upsampling, bounding-box prompts, Consistency and detail LoRAs are off.

FLUX 3 uses its distilled **16 steps**, flow-map sampling and no CFG. Klein uses its current distilled **four steps**, guidance 1.0 and native NVFP4 provider. A separate 256-square, one-step render warms each renderer and is excluded. Seeds are fixed within each model; equal seeds do not imply equal noise trajectories across architectures.

Timings include image/reference VAE work, denoising, raw PNG save, final PNG save and compositing. They exclude downloads and cold startup. Main FLUX 3 renders use separately cached prompt embeddings; main Klein seed 7 includes current streamed prompt encoding and seed 42 reuses its prompt cache. **Compare seed-42 rows for the cached-prompt timing table.** The separate lifecycle probe includes component reloads for a new FLUX 3 prompt.

Memory records distinguish peak PyTorch CUDA allocated/reserved memory, sampled process RSS, minimum available system RAM and sampled whole-card usage via `nvidia-smi`. Whole-card measurements include desktop/driver allocations. They are not interchangeable with tensor allocation. Memory guards reserve physical GPU headroom and stop low-RAM loading/rendering; they do not identify a model's universal minimum hardware requirement.

### Windows native NVFP4 adaptation

The official package contains 198 quantized matrices. Its even-low packed nibbles and row-major FP8 scales are converted once to Comfy Kitchen's even-high nibbles/cuBLAS scale tiles. There is no weight requantization or BF16 weight-matmul fallback. The adapter retains calibrated global/activation scales and explicitly casts flow-map FP32 inputs to BF16, as BFL's own NVFP4 linear does.

The numerical probe reconstructs the published format independently: converted weight dequantization is bit-exact, and the native GEMM differs by about 0.38% relative L2 from BF16 GEMM on the same quantized operands. Every completed FLUX 3 render records **3,168 native NVFP4 linear calls** (198 × 16). Strict state-dict loading proves the unquantized remainder is present.

Klein's stock loading sequence temporarily keeps the CPU renderer beside the streamed encoder. With background RAM usage this triggered the loading guard. The benchmark places the same renderer on CUDA before loading the unchanged encoder, reducing transient host overlap; its inference, weights, prompt cache and sampling remain the application's. Its cold-start number therefore describes this benchmark load order, not an unchanged app launch.

The first FLUX 3 Anna attempt failed on a reference width that was not a multiple of 16; both failed seeds are retained in `attempts/`. After the common reference fit, both succeeded. These setup/input failures are not silently counted as successful first attempts.

## Complete prompt-to-file lifecycle

The bounded Windows prototype cannot keep the full BF16 encoder and renderer resident together within the allocated GPU budget. For a new prompt it releases the renderer, loads the encoder directly onto CUDA, encodes, releases the encoder and reloads the renderer. All those operations, reference encoding, generation and both PNG writes are included below. A cached prompt retains its text embeddings and renderer. No download is included.

| Case | Klein new prompt, primary seed 7 | FLUX 3 new prompt, complete request | FLUX 3 cached prompt |
| --- | ---: | ---: | ---: |
| Two-person coaster | 6.083 s | 20.193 s | 10.694 s |
| Glowing mushroom | 1.774 s | 11.550 s | 2.416 s |
| Typography | 3.341 s | 17.504 s | 6.204 s |

All six complete FLUX 3 requests succeeded. New-prompt encoding/component setup consumes 5.685–7.193 s before renderer reload. The maximum request peak is **9.386 GiB allocated / 9.975 GiB reserved**, **7.486 GiB process RSS**, and **14,758 MiB whole-card usage**. The minimum sampled available system RAM is 4.241 GiB. The harness's initial component load and kernel warm-up take 26.560 s, excluded from these warm-request timings; this is not an optimized app cold-start measurement.

All six lifecycle outputs are **pixel-identical** to their primary cached-embedding outputs. This validates the direct-CUDA encoder loading and sequential component switching on these cases, rather than merely showing separate components that cannot complete a request.

This is a practical 16 GB path with a significant per-new-prompt reload cost. A production provider could investigate a smaller/streamed encoder and caching, but no such unmeasured speedup is assumed here. The experiment does not validate every resolution, ten-reference workload or 4K rendering.

## Current-prompt control and decision

The current application-style Klein control completed **24/24 images**, with a cached-prompt median of **3.14 s**, essentially the same as 3.17 s with matched captions. Its CUDA tensor peak is also 11.052 GiB. The same-prompt coaster/typography controls are pixel-identical across the two independent Klein processes: four exact repeat pairs.

Prompt style materially changes some local edits. The current prompts fix Klein's seed-42 daisy miss, make the reference mugs smaller/more plausible in the garden, and give Anna a more frontal, parallel-legged pose. The glowing-mushroom advantage remains, while both whole-image sword seeds change/add the second hand. These controls reduce the case for replacing the current editor default based only on a few favourable FLUX 3 images.

**Decision, confirmed with the user on 15 October 2026:** do not integrate FLUX 3; keep current Klein 9B as Quality. The selective identity, scene-following and typography gains do not justify roughly twice the cached render time and the additional cost for new prompts. A future small-model candidate must be substantially faster end to end at comparable quality, or clearly improve difficult editing cases. Fewer parameters and fitting in 16 GB alone do not meet that requirement. Preserve this benchmark as decision evidence.

No FLUX 3 provider integration is planned. This experiment does not validate application caching, native selection/expansion UX, cancellation/unload or the existing Consistency/Enhance features. Bounding-box prompting and the separate prompt upsampler were not evaluated and cannot be claimed as fixes for the observed scale/grip/mask limitations.
