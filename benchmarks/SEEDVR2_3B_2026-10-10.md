# SeedVR2 3B image restoration — 10 October 2026

Status: requested local GPU test completed. Twenty-seven outputs are retained: six source images with native 2x and half-size reconstruction; two seeds/repeats on the three faces; and three native colour-correction ablations. This adds research tools and evidence. SeedVR2 is not an app provider or an Export feature. User visual acceptance remains open.

## Decision

**SeedVR2 3B is the more promising candidate for adding visible skin, hair and cloth detail to these sources.** Compared with the [classical SwinIR Light experiment](UPSCALING_FIDELITY_2026-10-10.md), the man gains individual beard hairs and forehead wrinkles; the portrait gains fine skin structure and eyelashes. This better addresses the user's complaint about smooth faces. It also redraws content: eyes and teeth differ, fabric gains a different weave and golden stitching, and flowers become different, more defined flowers. The real-camera face becomes distinctly retouched, with opened eyes and altered small facial features. This is inferred detail, not verified recovery of the original high-resolution subject.

The [authors describe SeedVR2 as one-step generative restoration](https://github.com/ByteDance-Seed/SeedVR). Its [3B checkpoint](https://huggingface.co/ByteDance-Seed/SeedVR2-3B) is a different restoration route from classical source-preserving SR. One step does not imply zero changes to identity or object content. The outputs here support an optional manual/Export preview with Apply/Undo, rather than accepting this as a universal photo default. Keep text/logo layers out of the generative pass. Raw-edit postprocessing and protected-mask compositing have not been tested with SeedVR2.

SwinIR Light remains the source-preservation candidate; SeedVR2 remains the extra-detail candidate. Visual review must decide whether its face changes are acceptable. No automatic face restoration, extra sharpening, added film grain or hidden second diffusion pass is used in this experiment.

## Hardware, dependencies and recipe

RTX 5070 Ti 16 GB, driver 617.42, Ryzen 7 9700X, 32 GB RAM, Windows, Python 3.13.13, PyTorch 2.14.1+cu130/cuDNN 92400, torchvision 0.29.1+cu130, NumPy 2.5.3, Diffusers 0.41.0, Transformers 5.19.0. The app environment is unchanged. Additional wheels are isolated under `data/seedvr2-3b-2026-10-10/dependencies`, with versions and downloaded wheel hashes in `dependency-manifest.json`:

- OmegaConf 2.4.0, rotary-embedding-torch 0.9.1, OpenCV headless 5.0.0.93, GGUF 0.19.0, PEFT 0.21.2, einops 0.8.2.
- Matplotlib 3.11.2 and its missing wheel dependencies for the vendor import surface, recorded in the manifest.

The recipe uses one image frame / one Euler step, PyTorch SDPA attention, eight CPU threads, TF32 allowed, native CUDA allocator, no compilation, no SageAttention/Flash Attention/Triton. The vendor's PyTorch 2.9+ Conv3d workaround is active. Both VAE encode/decode use 512px tiles and 64px overlap when required. This tiles the VAE, not independent spatial diffusion crops. DiT block swapping is disabled. DiT, VAE and intermediate tensors offload to CPU between phases; cached model objects are retained in RAM between images. Unused CUDA cache is released before each measured generation.

Input and latent noise scales are zero. The baseline uses the port's LAB colour correction; a separate three-face run disables it. These settings reduce deliberately added variation but do not turn off generative content changes.

An initial wrapper import failed before inference because the vendor selected `cudaMallocAsync` after the wrapper had already imported Torch with the native allocator. The wrapper now selects native allocation **before** importing Torch, leaving vendor source untouched. That harness failure is retained in `bootstrap-failure.json` and is excluded from model-quality/performance results.

## Frozen inputs and all outputs

The same six cases and reference PNG hashes as the [classical 2x report](UPSCALING_FIDELITY_2026-10-10.md#frozen-cases-and-comparison-method) are used: the 832 x 1216 man, 512² portrait/denim crops, 512² public-domain NASA astronaut photo, 1024² garden crop and 1024² deterministic text/line image. The real-photo download source/license/hash are recorded there. Other photos are synthetic local fixtures. This is a bounded comparison, not a representative restoration dataset.

Baseline seed 7: **12 outputs**, native 2x plus half-size downsample/reconstruction for every source. Faces: **12 outputs**, native 2x for man, portrait and real photo at seeds 7/42 with two repeats each. Colour-none: **3 outputs**, native 2x on those faces at seed 7. All images and timing JSON are retained. No failed or less flattering quality cases were discarded.

Source/SwinIR/SeedVR2 review crops use identical source coordinates. Native source columns use nearest-neighbour 2x to expose the actual existing pixels; source and both outputs share the same displayed dimensions. Reconstruction uses the identical Lanczos half-size input and compares with the untouched source. The page also links Lanczos and full SeedVR2 PNGs, and preserves every repeat/seed/colour ablation.

Elapsed processing includes preparation, model movement from cached CPU weights, VAE encode, DiT inference, VAE decode, colour correction and output tensor transfer to CPU. Conversion to 8-bit PNG/save is measured separately. These warm timings keep model objects cached in RAM; they do not keep both models permanently on GPU.

| Real photo | 512² -> 1024² | **3.518 s**, median of four samples | 0.094 s, median | **3.612 s**, sum of medians |

The first face-seed sample is excluded from the warm man median. It costs **18.385 seconds**, including initial model materialization/CUDA work. The earlier baseline's first reconstruction costs **15.716 seconds** for a 416 x 608 input -> 832 x 1216 output. The no-colour run's first native man costs 17.730 seconds. CLI import alone costs about **14 seconds** per fresh benchmark process; checkpoint hashing, Python startup and downloads are additional and outside generation timing. Do not present a warm nine-second render as a cold first click.

Memory is observed at 50ms intervals, taking the maximum current CUDA allocator peak while the vendor resets its own phase statistics. It can miss very short allocations and excludes other apps/driver allocations. Process RSS is sampled, not total Windows committed RAM:

| Native output size | Observed peak CUDA allocated / reserved | Sampled process RSS |
|---|---:|---:|
| 1024² output | 7.080 / 8.897 GiB | About 9–10 GiB across runs |
| 1664 x 2432 output | 8.827 / 11.176 GiB | About 9–10 GiB across runs |
| 2048² output | 8.903 / 11.264 GiB | Up to 9.902 GiB in the baseline |

All 27 runs complete on the 16GB card without an OOM. **Klein is unloaded during these tests. Coexistence with loaded Klein 9B is not measured or approved.** The independent SR memory figures cannot be added to the old SwinIR residency conclusion. A shared-runtime recipe requires its own test, potentially with block swapping or another precision; quality changes from those recipes would need comparison too. No larger 3MP input/4K-wide SeedVR2 export was measured.

## Quality, seeds and colour

Inspection covers all 12 baseline crops, the three seed-42 native face crops and all three no-colour crops. Repeated images are checked for exact equality:

- Same seed and input: **zero changed pixels** for all six repeat pairs (three faces x two seeds).
- Seed 7 in two independent processes: **zero changed pixels** for all three native faces, including different ordering/initial materialization.
- Seed 7 versus 42 changes fine detail. Mean absolute 8-bit channel delta is 1.821 / 4.860 / 2.555 for man / portrait / real photo, with large localized differences possible. These are pixel differences, not identity scores. The broader reconstruction/retouch character remains similar in both inspected seeds.

LAB keeps colours closer to the input in these three native faces. Disabling it gives mean-image consistency PSNR 27.224 / 26.044 / 25.728 dB, versus LAB's 34.165 / 28.161 / 29.501. No-colour faces look warmer/oranger; disabling it does not fix inferred eyelashes, eyes, teeth or face detail. Keep LAB for the next preview candidate. Neither consistency PSNR nor colour correction proves correct high-resolution detail.

| Half-size reconstruction PSNR, dB | Lanczos | SwinIR Light FP32 | SeedVR2 3B LAB |
|---|---:|---:|---:|
| Man / beard | 36.036 | 39.687 | 30.225 |
| Portrait / skin | 33.325 | 35.549 | 24.268 |
| Real photo | 31.030 | 34.267 | 25.046 |
| Denim | 31.557 | 32.687 | 22.955 |
| Garden | 29.141 | 31.399 | 20.190 |
| Text / lines | 26.382 | 34.804 | 26.207 |

These losses confirm substantial source changes in the controlled reconstruction diagnostic. PSNR alone cannot rank subjective naturalness; the visible beard/skin changes can be appealing despite lower pixel fidelity. Native enlargement has no 2x ground truth, and its JSON `reference_psnr` is only downsampled consistency.

Specific limits: reconstructed small text becomes malformed; native text gains ringing/contour changes with little benefit. Denim acquires a new weave and thread colour, and garden flowers are reconstructed as new forms. The real photo shows a noticeable cosmetic/identity shift. The man and synthetic portrait gain finer texture but also changed eyes/eyelashes and deeper invented creases. These negative results stay alongside the better-looking detail. Alpha-edge behaviour, exact protected compositing, mask integration, cancellation and full-frame versus tiled VAE differences are not tested here.

## Reproduce and review

Download the pinned vendor archive above and extract under `data/seedvr2-3b-2026-10-10/vendor/`, keeping its commit-suffixed directory name. Install only the missing pinned wheels from `dependency-manifest.json` into the isolated dependency folder using the existing backend Python; do not replace Torch or install a ComfyUI server. Download the two exact safetensors from the pinned model revision into `models/research-cache/SeedVR2-3B/`; verify the hashes above. The existing real-photo fixture from the classical report must be present.

Run sequentially, with no loaded API pipeline or editor job:

```powershell
cd backend
$seedRoot = Join-Path (Split-Path $PWD) 'data/seedvr2-3b-2026-10-10'
$seedTemp = Join-Path $seedRoot 'temp'
New-Item -ItemType Directory -Force -Path $seedTemp | Out-Null
$env:TEMP = $seedTemp
$env:TMP = $seedTemp
$env:PYTHONIOENCODING = 'utf-8'
$env:MPLCONFIGDIR = Join-Path $seedTemp 'matplotlib'
$env:PYTORCH_CUDA_ALLOC_CONF = 'backend:native'
$env:HF_HUB_OFFLINE = '1'
$env:TRANSFORMERS_OFFLINE = '1'
$seedVendor = Join-Path $seedRoot 'vendor/ComfyUI-SeedVR2_VideoUpscaler-4490bd1f482e026674543386bb2a4d176da245b9'
.venv/Scripts/python.exe tools/benchmark_seedvr2.py --vendor-path $seedVendor --dependency-path "$seedRoot/dependencies" --output "$seedRoot/baseline"
.venv/Scripts/python.exe tools/benchmark_seedvr2.py --vendor-path $seedVendor --dependency-path "$seedRoot/dependencies" --output "$seedRoot/face-seeds" --cases face portrait astronaut --operations native --seeds 7 42 --repeats 2
.venv/Scripts/python.exe tools/benchmark_seedvr2.py --vendor-path $seedVendor --dependency-path "$seedRoot/dependencies" --output "$seedRoot/color-none" --cases face portrait astronaut --operations native --color-correction none
.venv/Scripts/python.exe tools/summarize_seedvr2.py
```

Tools: [benchmark runner](../backend/tools/benchmark_seedvr2.py), [review generator](../backend/tools/summarize_seedvr2.py). Ignored artifacts: `data/seedvr2-3b-2026-10-10/index.html`, all full/cropped PNGs, three `results.json` files, `repeat-equivalence.json`, `seed-variation.json`, pinned vendor/model/dependency manifests and the excluded bootstrap failure. All generated tensors pass finite-value and exact-output-size checks. The six frozen reference hashes match the SwinIR cohort. Backend/app and new-tool compilation, frontend build and local documentation/review-link checks pass. No production runtime, app dependency list, UI toggle, desktop executable, commit or push was changed for this experiment.
